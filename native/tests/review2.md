## 性能 A/B

两份二进制运行相同生成器，每场景各 3 个新进程，单线程索引；串行执行，未清 OS 页缓存。
“索引就绪”在 workspace/symbol 返回后计时，避免仅把索引移出 initialize 就宣称提速。
下面是中位数，不是任意工程或旧机器的性能承诺。

| 场景 | 4998dac | review2 |
| --- | ---: | ---: |
| 600 源共享 2 万行宏头：索引就绪 | 12523.23 ms | 83.33 ms |
| 300 个同名头中修改一个 | 305.45 ms | 3.11 ms |
| 20 个约 7 MiB 文件：峰值 RSS | 214.31 MiB | 79.94 MiB |
| 2 万引用：查询返回 | 2007.61 ms | 206.83 ms |
| 无关 Created：20 个打开源的分析次数 | 20 | 0 |

内存样本每个文件含 5 万个 wire/assign，并用注释补齐到约 7 MiB，专门检查源缓冲保留；
它不同于外部报告的原始网表样本。不要将两个环境的绝对 RSS/时延直接等同。
原始 30 条 JSON 数据、二进制 SHA256、构建参数和宿主日志随交付证据保存。
